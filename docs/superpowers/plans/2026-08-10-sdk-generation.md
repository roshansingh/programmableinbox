# Client SDK Generation (issue #124) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate ready-to-use client SDKs (Python, Go, TypeScript, Java, C#) for the v1 API from the existing OpenAPI spec, committed under `sdk/` in this repo, with each SDK verified to actually build/import.

**Architecture:** `lib/openapi/email-inboxes.ts` is the single source of truth. A small script exports it to `sdk/openapi.json`, which `openapi-generator-cli` (OpenAPITools) turns into five language-specific clients via per-language config files. Each generated directory gets a hand-written quick-start README that survives regeneration via `.openapi-generator-ignore`. All five SDKs use the same bearer-token auth the spec already declares (`ApiKeyAuth`), so no custom auth code is needed in any language.

**Tech Stack:** `@openapitools/openapi-generator-cli` (npm), JDK 11+ (generation only), Go toolchain, Maven (already installed), .NET SDK, Python 3, Node/npm.

## Global Constraints

- Package version for all five SDKs: `0.1.0` (matches the app's own `0.2.0`-adjacent pre-1.0 state; bump together later).
- Production API base URL: `https://app.programmableinbox.com` (from issue #124 — this is also the value that must replace the current placeholder in the spec's `servers` block).
- Repo/package identities (from issue #124's table — do not deviate):
  - Python: PyPI name `programmableinbox`
  - Go: module `github.com/roshansingh/programmableinbox-go`
  - TypeScript: npm name `@programmableinbox/sdk`, generator `typescript-fetch`
  - Java: Maven `com.programmableinbox:sdk`, generator `java` with `library=native`
  - C#: NuGet `ProgrammableInbox.Sdk`, generator `csharp`, `targetFramework=net8.0`
- Generated output is committed to git (not gitignored) — only build artifacts (node_modules, target/, bin/, obj/, egg-info, the intermediate openapi.json) are gitignored.
- Every `openapi-generator-cli` invocation needs Java on `PATH`. On this machine `java` is not linked to the system `/usr/bin/java` stub; Homebrew's OpenJDK lives at `/opt/homebrew/opt/openjdk/bin/java`. `sdk/generate.sh` must detect and handle this rather than assume `java` just works.
- Registry publishing (PyPI/npm/Maven/NuGet, triggered off a version tag) is explicitly **out of scope** for this plan — see issue #124.
- Per this repo's `CLAUDE.md`: run `npm run test` before considering the branch done for a PR.

- [ ] **Step 3: Write the generate script**

Create `sdk/generate.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

cd "$(dirname "$0")/.."

if ! command -v java >/dev/null 2>&1; then
  if [ -x "/opt/homebrew/opt/openjdk/bin/java" ]; then
    export PATH="/opt/homebrew/opt/openjdk/bin:$PATH"
  elif [ -x "/usr/local/opt/openjdk/bin/java" ]; then
    export PATH="/usr/local/opt/openjdk/bin:$PATH"
  else
    echo "error: java not found on PATH. openapi-generator-cli needs JDK 11+." >&2
    echo "Install with: brew install openjdk" >&2
    exit 1
  fi
fi

echo "==> Exporting OpenAPI spec"
npm run --silent sdk:export-spec

GEN="npx --no-install openapi-generator-cli generate"

echo "==> Generating Python SDK"
$GEN -i sdk/openapi.json -g python -o sdk/python -c sdk/openapi-generator-config/python.yaml

echo "==> Generating Go SDK"
$GEN -i sdk/openapi.json -g go -o sdk/go -c sdk/openapi-generator-config/go.yaml

echo "==> Generating TypeScript SDK"
$GEN -i sdk/openapi.json -g typescript-fetch -o sdk/typescript -c sdk/openapi-generator-config/typescript.yaml

echo "==> Generating Java SDK"
$GEN -i sdk/openapi.json -g java -o sdk/java -c sdk/openapi-generator-config/java.yaml

echo "==> Generating C# SDK"
$GEN -i sdk/openapi.json -g csharp -o sdk/csharp -c sdk/openapi-generator-config/csharp.yaml

echo "==> Done. Review with: git status sdk/"
```

Run: `chmod +x sdk/generate.sh`

using ProgrammableInbox.Sdk.Client;

var config = new Configuration
{
    AccessToken = "sk_live_...",
};

var api = new EmailInboxesApi(config);
var inboxes = await api.ListEmailInboxesAsync();
Console.WriteLine(inboxes.Data);
```
